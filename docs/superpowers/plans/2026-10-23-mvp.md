# Telegram Bot Connector MVP Implementation Plan

> **For agentic workers:** Use test-driven implementation and independent final review. Complete each task with a failing behavior test, minimal implementation and a passing full suite.

**Goal:** Ship a single-Site, owner-authorized Telegram Bot connector for ChatGPT.

**Architecture:** A Worker exposes a public authenticated Telegram webhook and owner-only MCP operations. D1 stores messages, subscriptions, delivery leases and outgoing idempotency state. Public GitHub source is separate from deployment-specific Site metadata.

**Tech Stack:** JavaScript ES modules, Web Crypto, Fetch, D1/SQLite, Node.js 24 test runner, MCP 2026-07-28.

**Spec:** `docs/design.md`

## Global Constraints

- English-only project; no personal names, real account IDs, credentials or deployment identity in public source.
- Telegram Bot API only; private text messages and explicit numeric allowlists.
- One new Site; leave existing test deployments unchanged.
- Fail closed on incomplete owner/security configuration.
- No scheduled polling or separate inference API.

## Review Focus

- Forged platform identity headers: require hosted edge verification before exposure.
- Pending duplicate after failure: retry without dropping the message.
- Concurrent send and ambiguous network failure: do not silently duplicate a reply.
- Signing-key renewal and expired subscriptions: stable identity and no unauthorized delivery.
- Callback SSRF and redirects: exact trusted origins, bounded response and no redirect following.
